# Out-of-scope находки (Stage 1)

Замеченное при аудите, но за рамками текущей задачи. Не править сейчас.

## Производительность

- **OOS-1.** `transform()` всех моделей кроме ESN — Python-цикл по T. Для FHN/LSM/Deep ESN при N≥200 и T≥2000 это десятки секунд на один прогон. Numba/Cython или векторизация (где возможно — Logistic, QRC можно полностью векторизовать) дала бы 10-50× ускорение. Не критично для ВКР; критично для будущих 1000+ trial HPO.

- **OOS-2.** `np.linalg.eigvals` на полной матрице `N×N` для перенормировки спектрального радиуса — `O(N^3)`. При N=1000 это ~1 секунду на инициализацию. Альтернатива — `scipy.sparse.linalg.eigs(W, k=1, which='LM')` для разреженных матриц — `O(N²)`. Для текущих размерностей не блокирует.

## Архитектура

- **OOS-3.** `experiment_runner.py` возвращает `dict`, а не Pydantic-модель. Это расходится с остальным контрактом (где всё через `pydantic.BaseModel`). Технический долг.

- **OOS-4.** `ridge.py:select_alpha` пересматривает alpha-grid вручную, хотя можно `sklearn.linear_model.RidgeCV` с тем же фунционалом — нативно, быстрее. Не критично.

- **OOS-5.** В `qrc_service.py:79` строка `x = features[: self._n_qubits]  # carry forward driven state` — driven состояние берётся из первого блока virtual nodes. Корректно, но не очевидно — комментария мало.

## Тесты

- **OOS-6.** В `tests/test_reservoirs.py` нет numerical-stability теста: «после 1000 шагов на случайном входе `H.std() > 1e-3 and H.std() < 100`». Это поймало бы проблему 1.5.1 (FHN dt большой ⇒ численная диффузия / blow-up).

## Методология (методически правильнее, инженерно дороже)

- **OOS-9.** Перенормировать выход reservoir `H ← H / √N` (или `H ← H / std(H_train)`) перед Ridge. Тогда оптимальный `readout_alpha` сместится в литературный диапазон `[1e-8, 1e-2]` (см. 02_hpo_spaces.md §2.8.1) и облегчит сравнение с публикуемыми числами. Сейчас `H` отдаётся «as is», и α ∈ [1e-6, 1e+2] — выбран по smoke-тесту.
