# Agent Workflow

## Роли

Постоянная команда ограничивается основным агентом и максимум тремя независимыми рабочими ветками.

| Роль | Область | Разрешённые задачи |
|---|---|---|
| Основной агент | контракт и интеграция | схемы, pipeline, RunRecord, backlog, решения, merge и release gate |
| Architecture & Quality | корректность и CI | `COR-*`, `TEST-*`, `CI-*` |
| Data & Experiments | данные и метрики | `DATA-*`, `EDA-*`, `BASE-*`, `MET-*`, `EXP-*` |
| Verification & JMLC | независимая проверка | `PROF-*`, `EVID-*`, `PLOT-*`, `DOC-*` |

Роли не являются постоянными персонами: сабагент создаётся под конкретный task ID и завершается после handoff.

## Когда использовать сабагента

Сабагент оправдан, если задача:

- имеет отдельный набор файлов;
- не требует одновременного изменения cross-cutting схем;
- имеет проверяемый Definition of Done;
- может быть интегрирована одним коммитом.

Не делегировать:

- выбор или изменение project contract;
- разрешение конфликтов между ветками;
- финальную интерпретацию результатов;
- release gate;
- две задачи, изменяющие один и тот же файл.

## Карточка задачи

Основной агент передаёт:

```text
Task ID:
Goal:
Base commit:
Allowed paths:
Forbidden paths:
Required reads:
Acceptance tests:
Expected artifacts:
Stop conditions:
```

Без этой карточки сабагент работает только read-only и возвращает анализ.

## Изоляция

Пример:

```bash
git fetch origin
git worktree add ../rc-bench-COR-001 -b codex/COR-001-split-fix dev
git worktree add ../rc-bench-DATA-002 -b codex/DATA-002-uci-loader dev
```

Один worktree — один task ID — один агент. Владелец задачи не изменяет чужой worktree и не выполняет merge в `dev`.

## Контроль результата

Сабагент обязан:

- сообщить base и final commit SHA;
- перечислить изменённые файлы;
- привести команды и фактический результат тестов;
- указать риски и непроверенные предположения;
- заполнить handoff;
- не заявлять готовность при упавшей обязательной проверке.

Основной агент:

1. проверяет diff;
2. сопоставляет его с task scope;
3. запускает acceptance tests;
4. интегрирует один коммит;
5. запускает общий quick gate;
6. обновляет backlog;
7. только затем интегрирует следующую ветку.

## Предотвращение конфликтов

- Ownership назначается по путям, а не только по смыслу задачи.
- `schema.py`, `pipeline.py`, `run_record.py`, `BACKLOG.md` и `DECISIONS.md` меняет основной агент либо один заранее назначенный владелец.
- Документационный агент читает evidence, но не изменяет вычислительное ядро.
- Экспериментальный агент не редактирует README до завершения evidence bundle.
- Если требуется общий файл, сабагент предлагает patch или интерфейс в handoff, но не меняет файл без разрешения.

## Интеграционный порядок

```text
correctness → data contracts → baselines/metrics → profiling
→ smoke → full matrix → evidence → docs → release
```

Параллельно допускаются только независимые пары, например EDA после стабилизации loader и CI после стабилизации unit mode.
