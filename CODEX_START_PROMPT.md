# Стартовый промпт для Codex

Работаем с репозиторием `ReFlex-cmd/rc-bench` перед защитой JMLC 27 июля 2026 года.

Рабочая ветка проекта — `dev`; `main` используется только как цель финального PR. Текущий удалённый `dev` исторически отставал от `main` и содержит старые аудиты и `graphify-out`. Сначала проверь актуальное состояние веток. Если оно не изменилось, сохрани старый `dev` в архивной ветке, затем fast-forward синхронизируй рабочий `dev` с `main`. Не возвращай удалённые кэши, `graphify-out` и архивные материалы в актуальную историю.

Прочитай полностью:

- `AGENTS.md`;
- `docs/agent/AUDIT_BASELINE.md`;
- `docs/agent/PROJECT_CONTRACT.md`;
- `docs/agent/WORK_PLAN.md`;
- `docs/agent/BACKLOG.md`;
- `docs/agent/DECISIONS.md`;
- `docs/agent/AGENT_WORKFLOW.md`.

На первой итерации выполни только подготовительный gate:

1. Проверь чистоту рабочего дерева, remote, ветки и отношение `dev` к `main`.
2. Безопасно подготовь актуальный `dev` согласно `WORK_PLAN.md`.
3. Убедись, что repository-native harness находится в ожидаемых путях.
4. Запусти `bash scripts/verify.sh quick`.
5. Сопоставь фактический результат с задачами `BOOT-001`, `BOOT-002`, `COR-001` и `COR-002`.
6. Верни короткий отчёт: что подтверждено, что изменилось с момента аудита, какие команды прошли, какой следующий task ID предлагается взять.

Не начинай real-data реализацию, не запускай полный эксперимент и не делай PR в `main` на первой итерации. Если состояние веток отличается от описанного, остановись после read-only анализа и предложи безопасный вариант синхронизации.
